# Диагностика TLS по ALPN, версии TLS и семейству IP

`tls-diagnostics` сравнивает обычные TLS-рукопожатия с одним DNS-именем
на порту 443. Для предварительного просмотра плана не нужны сеть и привилегии.

```bash
go run ./cmd/tls-diagnostics example.com
```

После проверки цели по [правилам проекта](../../docs/SAFETY.md) оператор
может подтвердить имя и запустить план.

```bash
go run ./cmd/tls-diagnostics -confirm-target example.com example.com
```

| Профиль | Адрес | Предложение ALPN | Версии TLS |
| --- | --- | --- | --- |
| `baseline-ipv4` | IPv4 | `h2`, `http/1.1` | 1.2–1.3 |
| `http1-alpn` | тот же IPv4 | `http/1.1` | 1.2–1.3 |
| `tls12` | тот же IPv4 | `h2`, `http/1.1` | 1.2 |
| `baseline-ipv6` | IPv6 | `h2`, `http/1.1` | 1.2–1.3 |

Команда использует первый адрес каждого семейства от системного резолвера.
Для всех подключений SNI и проверка сертификата используют заданное имя.
На каждый DNS-запрос по семейству и каждое подключение отводится до четырёх
секунд. Подключения выполняются последовательно по одному разу на профиль.
`Ctrl+C` прерывает текущую операцию и отменяет оставшиеся попытки.

JSON содержит выбранные адреса, ошибки DNS и исходы на стадиях TCP и TLS.
При успешном рукопожатии записывается согласованная версия TLS и ALPN,
если сервер его выбрал. Для семейства без адреса соответствующие профили
пропускаются. Ошибки подключения и пропуски остаются в JSON как наблюдения.
Команда выполняет только TLS-рукопожатие и не отправляет HTTP-запрос.

Сравнения ALPN и версии TLS используют один IPv4. На результат влияет
совместимость сервера или CDN. Сравнение IPv4 и IPv6 может затрагивать
разные маршруты и серверы. Команда не ведёт захват пакетов. Наблюдения
служат предварительной диагностикой и не устанавливают причину сетевого
сбоя или результат исследовательских вопросов B06/G03.
