# Инструкции для агентов DPIsect

## Контекст проекта

DPIsect — активный пробер для исследования DPI: диагностики сбоев TLS/TCP, поиска триггеров фильтрации и локализации сетевого вмешательства. [Исследовательская матрица](docs/RESEARCH_MATRIX.md) — каталог вопросов и предлагаемых экспериментов, а не свидетельство проведённых измерений. Приоритет P0 не означает автоматического включения всех таких вопросов в первый релиз.

Перед работой ознакомьтесь с [планом исследований](docs/DEVELOPMENT.md); для экспериментальных задач прочитайте соответствующие строки матрицы и [методологию](docs/EXPERIMENTS.md). Не представляйте гипотезы как подтверждённые результаты. Если требования, границы задачи или технические решения не определены и их нельзя надёжно вывести из проекта, уточните их у пользователя вместо того, чтобы выдумывать.

## Разработка

- Сохраняйте стабильные ID вопросов матрицы. Для исследовательской задачи определяйте вопрос, контроль или fixture, ожидаемые артефакты и критерий завершения.
- Используйте Go. Linux — основная целевая платформа. Явно обозначайте платформенные ограничения и не выдавайте непроверенную совместимость за реализованную.
- Разделяйте назначение генератора проб, runner, capture, helper и анализатора. Конкретная архитектура, версия Go, зависимости и команды запуска пока не зафиксированы; не выдавайте предполагаемые решения за утверждённые.
- Для изменений выбирайте проверки, соответствующие задаче, и сообщайте фактические результаты и ограничения. Не утверждайте, что проверка прошла, если она не выполнялась.
- Документацию и тексты PR пишите на русском языке.
- Не удаляйте и не перезаписывайте чужие изменения без явного разрешения.

## Git и завершение задачи

Соблюдайте [правила Git](docs/GIT_WORKFLOW.md): проверяйте состояние рабочего дерева, используйте подходящую ветку или создавайте новую, делайте атомарные коммиты по Conventional Commits и сохраняйте чужие изменения.

Если в ходе задачи создана одна или несколько веток, последним шагом предоставьте название и описание PR для каждой созданной ветки. Укажите фактические изменения, результаты проверок и существенные ограничения. Подготовка текста PR сама по себе не означает его публикацию.
