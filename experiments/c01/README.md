# C01. Сегментация ClientHello

Этап 2 зафиксировал повторение [клиентского симптома](../b01/google-youtube/stage2-conclusion.md)
с причинным статусом `inconclusive`. В C01 сравнивается наблюдаемый
ответ при разных границах TCP-сегментов до, внутри и после SNI.
Контроль содержит ClientHello без разбиения. Инварианты — SNI, TLS
профиль и границы TLS records, endpoint и условия измерения. Байт-в-байт
равенство проверяется по заранее сохранённым сообщениям. При отдельных
TLS-сессиях со свежей случайностью каждый ClientHello сверяется со своим
планом, а различия между сессиями учитываются в выводе; такой дизайн
ограничивает силу сравнения относительно канонического C01.

## Проверка сохранённого захвата

Из корня репозитория с установленным Go 1.27.3 и кешем зависимостей
выполните команду, подставив локальные пути и адрес клиента из PCAP.
Для выбора попытки используйте её номер в плане и исходный IP:порт её SYN.

```bash
GOTOOLCHAIN=local GOPROXY=off GOSUMDB=off go run ./experiments/c01/review \
  -plan path/to/plan.yaml -pcap path/to/client.pcap \
  -trial 1 -source 192.0.2.1:40000
```

Команда читает локальный Ethernet PCAP и план в формате существующего
runner. Она проверяет фактические байты ClientHello от начала TCP-потока
по SYN и sequence numbers. Поддерживаются IPv4/TCP и ClientHello в одном
или нескольких TLS records. План содержит `trials[].sni` и
`trials[].packet` с `payload` и `tls_record_ends`. Если план задаёт
`split_offsets`, команда сравнивает его с захватом. Пустой список
означает ожидаемый одиночный TCP-сегмент, поле можно опустить для
проверки без ожидаемой границы. В планах этапа 2 пустой список обозначал
управление сегментацией ядром, поэтому там сравнение с пустым списком
описывает наблюдение, а не предписание эксперимента.

В JSON `tcp_split_offsets` — границы по TCP sequence space, а
`tls_record_ends` — концы TLS records. Обе координаты отсчитываются
от первого байта TLS-потока. `first_seen_segments_in_capture_order`
сохраняет номера кадров, порядок появления диапазонов и размер TCP
payload, включая возможные байты после ClientHello. Команда считает
повторы уже виденных диапазонов, а также входящие кадры и кадры с TCP
payload между сборкой ClientHello в захвате и первым таким повтором.
При отсутствии повтора окно длится до конца захвата. Если повтор был
до появления всех байтов ClientHello, это окно пустое. Дубликат
захвата может выглядеть как повтор диапазона.

Команда завершится ошибкой при пропуске или несовпадении байтов,
смешении новых и повторных байтов в одном TCP-сегменте, неоднозначном
переиспользовании TCP-четвёрки, усечённом кадре или обнаруженной
IPv4-фрагментации TCP между выбранными адресами. Она выдаёт хэши плана,
захвата и байтов ClientHello. Перед выводом сверяйте хэши, расположение
захвата и состояние offload. Клиентский PCAP показывает наблюдение в
точке захвата. Доставку и сборку на стороне сервера подтверждает
отдельное наблюдение. Правило оценки сетевой серии фиксируется до
первого пакета и применяется к наблюдениям до остановки.

Для нескольких захватов используйте `-series` и [критерии сравнения C01](route-review.md).

## Пассивный захват браузера

Для захвата без `plan.yaml` укажите файл и видимое имя TLS:

```bash
GOPROXY=off go run ./experiments/c01/review \
  -browser artifacts/c01-browser-passive-2026-11/browser.pcapng \
  -sni www.youtube.com
```

Команда читает Ethernet PCAP и PCAPNG с одного интерфейса. Она ищет
TCP/IPv4 на порту 443 с клиентским SYN и одним полным TLS record
ClientHello, собранным из непрерывных исходящих диапазонов TCP.
В JSON выводятся SHA-256 захвата и ClientHello, первые границы TCP,
совпадающие повторы и счётчики входящих кадров. Смещения имени SNI
выводятся, когда последовательность байтов имени единственная в записи.
При ECH видно только внешнее имя SNI. QUIC, неполные сообщения и
сообщения с разрывом до завершения первого record в разбор не попадают.
Пределы одного запуска — 64 МиБ, 4096 незавершённых потоков и
256 совпадений.
Пустой список означает, что подходящий поток в поддерживаемом формате
не найден.

## Проверка на изолированном loopback

Тест использует обычный TCP на `127.0.0.1` и один ClientHello для
четырёх вариантов. Приёмник читает каждый диапазон до следующей записи
клиента и сверяет восстановленные байты. Разбор проверяет фактические
границы сегментов по PCAP. Используется контроль без разбиения и по
одному разбиению до, внутри и после SNI. Тест проверяет метод измерения
в локальных условиях. Для вывода об исходном симптоме нужны наблюдения
на исследуемом маршруте.

Для запуска из корня репозитория нужны Go 1.27.3 с кешем зависимостей,
`unshare`, `ip` и доступ к пользовательским сетевым пространствам имён.
`CAP_NET_RAW` действует внутри временного пространства имён.

```bash
unshare -Urn sh -c 'ip link set lo up &&
  GOPROXY=off go test -tags privileged -v -count=1 \
    -run "^TestC01LoopbackSegmentation$" ./experiments/c01/review'
```

## Проверка полной TLS-сессии

`TestC01LoopbackVerifiedTLS` проверяет TLS 1.3 с валидацией сертификата
и обменом HTTP на локальном Go-сервере. Контроль сравнивается с
вариантом на двух TCP-сегментах. Граница задана по смещению в потоке
и не зависит от SNI. Захват проверяет фактические TCP-границы и одну
TLS-запись в каждом ClientHello.

```bash
unshare -Urn sh -c 'ip link set lo up &&
  GOPROXY=off go test -tags privileged -v -count=3 \
    -run "^TestC01LoopbackVerifiedTLS$" ./experiments/c01/review'
```

Для сохранения PCAP запускайте каждый повтор с `-count=1` и новым
каталогом в `DPISECT_LOOPBACK_ARTIFACTS`.

## Проверка C03 на изолированном loopback

Тест создаёт отдельное пространство имён через `unshare` и использует
`netem` после TCP-handshake. Контроль и опыт используют одни байты и
одну границу. Проверяется порядок сегментов на приёмной стороне и
равенство байтов, прочитанных приложением. Для теста также нужен `tc`.

```bash
GOPROXY=off go test -tags privileged -v -count=1 \
  -run '^TestC03LoopbackReorder$' ./experiments/c01/review
```

`TestC03LoopbackVerifiedTLS` использует тот же изолированный режим и
дополнительно проверяет сертификат, завершение TLS 1.3 и HTTP-ответ при
обычном и обратном порядке доставки. Для повторения подставьте это имя
в `-run`.

Для loopback-проверок переменная `DPISECT_LOOPBACK_ARTIFACTS`
может указывать абсолютным путём на существующий приватный каталог вне git. PCAP
сохраняются под именами вариантов. Повторный запуск с тем же каталогом
не перезаписывает захваты. По умолчанию проверки хранят PCAP в памяти.
