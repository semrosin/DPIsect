# Пакетная диагностика DNS, TCP и TLS

Скрипт запускает `dpi-prober` последовательно по списку ресурсов. На
ресурс выбирается один IPv4 и порт 443. Проверка фиксирует DNS, SYN/SYN-ACK,
ClientHello, ответ TLS и результат проверки сертификата. Область
диагностики заканчивается на рукопожатии TLS.

## Входные данные

Передайте имена в аргументах или в текстовом файле, по одному на строку.
Можно добавить `#` с комментарием. Для международных доменов используйте
ASCII-имена Punycode.

```text
site.example
video.example=other.example # другой обычный HTTPS-сайт на том же IPv4
```

`HOST` задаёт до двух обычных попыток с SNI ресурса (A02).
`HOST=CONTROL` задаёт пару обычных TLS-подключений (B02). Используйте
известное рабочее контрольное имя, которое обслуживается на общем IPv4
и предъявляет действительный сертификат для себя. При отсутствии общего
IPv4 выполняется A02. В паре контроль запускается первым. Если монитор
остановит серию на контроле, отчёт покажет, что попытка ресурса не началась.

Обычный профиль использует штатный TLS-клиент пробера и параметры TCP
ядра. Пакетный запуск на чужих сайтах ограничен этим профилем по
[правилам проекта](../../../docs/SAFETY.md).

## Запуск с проверяемой машины

Из корня этой рабочей копии сначала просмотрите список. Этот режим не
отправляет пакеты.

```bash
experiments/a02/batch/run.sh -file /path/to/hosts.txt
# Или имена прямо в аргументах
experiments/a02/batch/run.sh site.example video.example=other.example
```

Перед запуском проверьте цели по Do Not Scan и условия для первой серии
из [SAFETY.md](../../../docs/SAFETY.md). Подготовьте только бинарь пробера
для захвата на выбранном интерфейсе.

```bash
go build -o bin/dpi-prober -ldflags "-X main.commit=$(git rev-parse HEAD)" ./cmd/dpi-prober
sudo setcap cap_net_raw+ep bin/dpi-prober
```

Передайте список, имя оператора и интерфейс, через который идут
подключения. Для остановки нажмите `Ctrl+C`.

```bash
experiments/a02/batch/run.sh -confirm-targets -iface eth0 -operator "$USER" -file /path/to/hosts.txt
sudo setcap -r bin/dpi-prober
```

На ресурс отводится до 14 секунд после DNS. Пауза между попытками
составляет три секунды. Монитор пробера прекращает серию при наблюдаемом
повторе SYN, данных или FIN, при проблеме с захватом или при приближении
к лимитам из [SAFETY.md §3](../../../docs/SAFETY.md#3-лимиты-серии).
После остановки одной серии скрипт переходит к следующему ресурсу.
При проблеме с артефактами итоговый код выхода ненулевой.
Если интерфейс отдаёт в захват кадры, объединённые offload, монитор
может остановить серию с сообщением о превышении MTU. Это отражается
в отчёте как причина остановки измерения.

## Отчёт

`artifacts/a02-batch/batch-*/<host>/report.md` начинается с диагноза,
например «TCP — отправлен SYN, SYN-ACK не получен» или «TLS — ошибка
проверки сертификата». Рядом сохраняются PCAP, конфигурация и журнал.
Скрипт связывает попытку с TCP-потоком по окну времени и клиентскому
порту. При нескольких потоках в окне вывод по пакетам помечается как
неоднозначный.

«Вероятна фильтрация по SNI» появляется, когда контроль завершил TLS
на том же IPv4, оба ClientHello совпали по размеру, а попытка ресурса
закончилась по таймауту или повтору данных без ответных TCP-данных и RST.
В отчёте отмечается различие размеров ClientHello, если оно могло повлиять
на сравнение.
Диагноз описывает наблюдение этой машины. Формальные исходы A02 и B02
определяются по [EXPERIMENTS.md §7](../../../docs/EXPERIMENTS.md#7-интерпретация-исхода).
